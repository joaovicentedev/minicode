04 / SPEC-DRIVEN + AGENT HARDNESS

Especificação, plano
e regras de conclusão.

ANTES DO CÓDIGO

Specification → Plan

A spec contém objetivo e critérios de aceitação. O plano descreve os passos. A implementação só é solicitada depois dos dois documentos.

ANTES DO SUCESSO

Tests → Review → DONE

O estado DONE exige pytest com código 0 e revisão de aceitação aprovada. Falha leva ao reparo ou a FAILED.

SPECIFIED ⇏ IMPLEMENTINGTESTS FAILED ⇏ DONE

A qualidade dos critérios da spec é avaliada pelo modelo; ainda não há validação estrutural automática desse texto.

Sem Docker ou sem a imagem de testes, o estado é UNVERIFIED. O código do projeto não é executado no host.

10 / LIMITES ATUAIS

Limites reais
do MiniCode.

EDIÇÃOCada proposta substitui o arquivo inteiro; não há edição por trecho.
VERIFICAÇÃOExecuta apenas pytest -q. Sem testes coletados, termina em UNVERIFIED.
ESPECIFICAÇÃOA spec é texto livre; a qualidade dos critérios não é validada automaticamente.
AMBIENTEDocker é obrigatório. A imagem padrão contém Python 3.13 e pytest, sem dependências extras do projeto.

O contexto inicial também é limitado a uma amostra de até 20 arquivos de texto e cerca de 24 mil caracteres.
